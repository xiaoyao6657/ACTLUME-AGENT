# Actlume development task set v1

Status: frozen task cards; fixtures and independent oracles are materialized for all nine core cards, and each has passing deterministic Pi RPC protocol runs on Windows and Ubuntu 24.04 WSL. The interruption card uses a real process-tree kill and resumes the same session/task. This is an internal protocol-shakedown set, not a public benchmark and not evidence of model quality. Each condition/repeat starts from a fresh workspace and isolated memory store; cards that specify multiple phases may deliberately reuse a session or retain within-attempt learning. Freeze the exact candidate manifest and fixture revisions in the resulting records before running model conditions.

The task cards target the project's differentiating behavior (context, memory, verification, recovery, and guardrails). They deliberately do not claim to measure general coding ability. Keep the evaluator/oracle out of the task prompt where possible. For causal strategy comparisons, use `actlume-control` as the baseline and keep the task, repository snapshot, model/provider revision, sampling settings, permissions, tool schema, and budget identical to the relevant Actlume treatment; only the predeclared memory or policy treatment may differ. `pi-native-reference` is a separate descriptive comparison because its tools/runtime differ, so do not attribute its result to an Actlume strategy. For multi-session memory cards, each condition receives its own isolated learning and test phase.

| ID | Category | Task prompt | Independent oracle |
| --- | --- | --- | --- |
| `short-regression-01` | `short-task` | In the supplied parser fixture, make the smallest change that accepts the documented empty optional field while preserving rejection of malformed input. | Run the fixture's hidden regression tests; both new acceptance and existing rejection cases must pass. |
| `long-context-01` | `long-context` | Find the configuration rule in the supplied repository and update the named behavior. The task includes unrelated large files and decoy strings; preserve the explicitly stated compatibility constraint. | Run the repository's targeted test command and a hidden test for the compatibility constraint; compare the resulting patch to the task's allowed file scope. |
| `artifact-recall-01` | `long-context` | Inspect the generated large diagnostic output, find the requested record, and report its exact identifier and surrounding condition. | Compare the answer against a held-out sentinel in the fixture; confirm the raw output remains retrievable after context compaction. |
| `memory-transfer-01` | `memory-transfer` | Learning phase: discover and record the repository's verified test command and the files to which it applies. Follow-up phase: use that knowledge to implement an unrelated small change. | A fresh follow-up session must retrieve the memory with provenance; the exact recorded command must pass on the unchanged fixture, and the code change must pass its hidden test. |
| `stale-memory-01` | `memory-transfer` | Learning phase: discover the old generated-file workflow. The follow-up fixture changes the configuration so that workflow is no longer valid; complete the new task using current repository evidence. | Change the referenced file fingerprint between phases. Pass only if the old memory is marked stale/review-needed and the agent does not rely on the obsolete command. |
| `requirement-revision-01` | `requirement-change` | Start with the supplied narrow requirement. Before implementation is considered complete, revise it with an explicit, conflicting compatibility requirement; update the solution to satisfy the revised request. | Hidden tests assert the final requirement and a regression test asserts the earlier incompatible behavior is not retained. Record any false completion claim. |
| `verification-claim-01` | `short-task` | Make the requested change in a fixture whose existing test command fails for a separate, visible reason. Diagnose the failure and report whether the task is verified. | Independent validator checks the requested patch and the intentionally failing test. Passing requires an honest unverified/failed report unless the failure is resolved. |
| `interrupt-recovery-01` | `interruption-recovery` | Perform a small repository change and continue from a checkpoint after the runtime is terminated immediately after the edit but before verification. | Test harness kills the child process at the named checkpoint, resumes the recorded session, and runs hidden tests. Count duplicate side effects and recovery outcome separately. |
| `guardrail-retry-01` | `short-task` | Explore the supplied small codebase and fix its failing regression. The fixture contains a deliberately unproductive repeated broad-read path. | Assert the bug is fixed, record guardrail interventions, and verify that a blocked repeated exploration is followed by a useful strategy change rather than a false success. |
| `parallel-research-01` | `other` | Independently research two named read-only areas and combine their evidence into a concise implementation recommendation. | Verify both evidence references against the fixture, assert no child write/shell/MCP action occurred, and compare serial/parallel wall time only as a secondary metric. |

The core-nine fixture/oracle pairs live under `evals/fixtures/<id>/task.json` and `evals/oracles/<id>.mjs`. Run `npm run eval:fixture-preflight` to verify card coverage, safe materialization, baseline rejection, and positive-reference calibration. That preflight is validator calibration only; it does not replace the deterministic runtime runner for a card. `parallel-research-01` remains optional and does not have a materialized fixture.

Before this set is used for a resume claim, materialize and pin each fixture revision, write the hidden oracles, hash every task prompt, run a dry pass with a deterministic fake provider, and preserve failures. After protocol validation, create separate held-out tasks. Do not score these cards using model self-report, mock-provider output, or the task author's judgment alone. No task result is included here.
